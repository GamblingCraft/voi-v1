# Архитектура ВОЙ

## Основа

Проект использует App Router Next.js. По умолчанию компоненты серверные; клиентские границы выделены для состояния, событий и браузерных API. Структура `features` — соглашение этого проекта, а не требование Next.js.

Основание: [структура проекта](https://nextjs.org/docs/app/getting-started/project-structure), [Server и Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components), [CSS](https://nextjs.org/docs/app/getting-started/css), а также документация установленной версии в `node_modules/next/dist/docs`.

## Границы компонентов

Категория собирается сервером из заголовка, категорий, боковой панели и результатов. Подбор товаров не зависит от React: `catalog-selection.ts` проверяет фильтры, сортирует копию массива и формирует ссылки сброса. Интерактивность карточки покупки и раскрытия фильтров находится в клиентских компонентах.

Страница товара и основное описание серверные. `ProductVariantProvider` хранит выбранный вес; маленький `ProductWeightText` показывает его в серверно сформированных характеристиках. `ProductSections` управляет вкладками и получает готовые серверные панели через `ReactNode`. Данные отзывов и вопросов помечены `server-only`; форма отправки выделена отдельно. Авторизация и модерация требуют будущей серверной интеграции: текущая гостевая форма недоступна, публичные записи демонстрационные.

`CatalogCard` используется каталогом, главной, похожими и просмотренными товарами. Изменение визуализации карточки выполняется здесь. Не создавайте отдельную копию карточки для главной.

Шапка управляет открытием превью и фокусом. Список корзины принадлежит `features/cart/components`, операции и сохранение — модели и хранилищу корзины. Общий источник данных связывает карточки и превью.

Посадочные разделены по страницам, общие hero / FAQ / CTA находятся в `content/components`. CSS Modules принадлежат компонентам; общие оболочки и типографические токены лежат отдельно. Сброс заголовков использует `:where`, чтобы не перекрывать стили компонентов из-за порядка CSS-чанков.

## Маршруты и SEO

Русские публичные пути не имеют языкового префикса. `proxy.ts` выполняет внутренний rewrite, без редиректов старых товарных адресов. Поддерживаются `/catalog`, `/catalog/[category]`, `/catalog/[category]/[slug]`; slug строится из названия без веса. Смена фасовки не меняет URL. Metadata и канонические ссылки остаются в маршрутах и `i18n/metadata.ts`. Сквозные подписи колонок футера — `div`, не заголовки.

## Проверка и очистка

`npm run check` проверяет lint, типы и тесты. `npm run build` проверяет production-сборку. `npm run audit:project` строит граф импортов от App Router, proxy и тестов, читает ссылки на публичные медиа и показывает кандидатов. Аудит эвристический: вычисляемые пути и будущие CMS-ресурсы требуют ручной проверки. Он ничего не перемещает и не удаляет.

Старые CSS, отключённые секции и неиспользуемые материалы находятся вне приложения в `../voi-archive/refactor-2026-10-06/unused`. Исходные версии переработанных файлов — в `before`, одноразовые скрипты — в `tools`. Конфигурация, тесты, `.git`, `node_modules` и `.next` остаются на месте, поскольку используются разработкой и сборкой.
